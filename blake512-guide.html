BLAKE-512
파일에서 해시까지, 한 단계씩

파일 내용을 블록으로 읽고, 그 안의 숫자를 작업 상태에 반복해서 섞습니다. 모든 블록을 처리한 뒤 남은 결과가 해시값입니다.

128바이트블록 하나의 크기
64비트숫자 하나의 크기
16라운드블록마다 반복
64바이트최종 해시 크기
이 문서는 원래 BLAKE-512를 설명합니다. 앞서 이야기한 BLAKE-256의 64바이트 블록·14라운드와 구분하세요. BLAKE2b와도 계산 규칙이 다릅니다.

전체 흐름 먼저 보기

입력 + 패딩
→
128바이트 블록
→
M 숫자 16개
→
V 준비
→
G × 8 × 16라운드
→
H 갱신

다음 블록이 있으면 갱신된 H를 사용해서 다음 블록을 처리합니다. 마지막 블록까지 끝나면 H를 64바이트로 출력합니다.

1먼저 이름을 구분하기

이름크기역할
M · 메시지64비트 × 16개현재 블록에서 읽은 재료. 블록 처리 중에는 그대로 둡니다.
V · 작업 상태64비트 × 16개G 함수가 계속 바꾸는 숫자들입니다.
H · 중간 해시64비트 × 8개한 블록의 결과를 다음 블록으로 이어 줍니다.
C · 고정 상수64비트 × 16개명세에 미리 정해진 값. 코드에서는 CB입니다.
s · salt64비트 × 4개추가로 지정하는 보조 값. 미사용 시 모두 0입니다.
t · 카운터128비트처리한 원래 메시지의 누적 비트 수. 패딩은 세지 않습니다.
M[0], M[1]은 블록 두 개가 아닙니다. 같은 블록 안에 있는 숫자 두 개입니다. 또 고정 상수 C와 salt s는 서로 다릅니다.

2입력 끝에 패딩 붙이기

파일은 바이트들의 나열입니다. 마지막에 정해진 정보를 붙여 전체 길이를 128바이트의 배수로 만듭니다. 파일을 여러 개 만드는 것이 아니라 계산 단위를 나누는 것입니다.

원래 메시지 | 1 | 필요한 만큼의 0 | 1 | 원래 길이 128비트

첫 1과 0들을 붙인 길이가 1024로 나눈 나머지 895가 되도록 맞춥니다. 그 뒤 1비트와 길이 128비트를 붙이면 1024비트의 배수가 됩니다. 길이는 빅엔디언으로 기록합니다.

현재 코드: 80바이트 입력

입력 80바이트 + 패딩 48바이트 = 128바이트 블록 하나

패딩 48바이트:
0x80 | 0x00 30개 | 0x01 | 길이 정보 16바이트
길이 정보: 상위 64비트 = 0, 하위 64비트 = 640
80바이트 × 8 = 640비트

입력이 이미 128바이트의 배수여도 패딩을 추가합니다. 필요한 정보가 마지막 블록에 들어가지 않으면 블록을 더 사용합니다.

3블록을 숫자 16개로 읽기

한 블록의 128바이트를 8바이트씩 묶어 64비트 정수로 해석합니다. 데이터는 같고, 읽는 단위만 바뀝니다.

바이트   0 ~   7 → M[0]
바이트   8 ~  15 → M[1]
                  …
바이트 120 ~ 127 → M[15]

128바이트 ÷ 8바이트 = 숫자 16개

빅엔디언은 앞 바이트를 높은 자릿수에 놓는 방식입니다. 예를 들어 00 00 00 00 00 00 01 02는 숫자 258로 읽습니다.

현재 80바이트 예제에서는 M[0]~M[9]가 입력이고, M[10]~M[15]가 패딩입니다.

4작업 상태 V 준비하기

첫 블록의 H는 정해진 시작값 IV입니다. 다음 블록의 H는 앞 블록에서 만든 결과입니다. 그 H와 salt·상수·카운터로 V를 준비합니다.

V0  V1  V2  V3    ← H0, H1, H2, H3
V4  V5  V6  V7    ← H4, H5, H6, H7
V8  V9  V10 V11   ← s0^C0, s1^C1, s2^C2, s3^C3
V12 V13 V14 V15   ← t0^C4, t0^C5, t1^C6, t1^C7

^는 XOR입니다. t0는 카운터의 하위 64비트, t1은 상위 64비트입니다. 이 코드에서는 salt가 모두 0이고, t0=640, t1=0입니다.

V를 준비한 직후에는 메시지 M을 직접 섞지 않았습니다. 다음 단계의 G가 M을 주입합니다. 같은 설정·카운터 조건이면 서로 다른 입력의 초기 V가 같을 수 있습니다.

5G 한 번: 네 작업 숫자에 메시지 숫자 두 개 섞기

G는 V에서 네 숫자를 선택해 a, b, c, d로 다룹니다. 현재 블록에서 메시지 숫자 두 개를 골라 고정 상수와 결합합니다.

p, q = 이번 G에서 선택한 메시지 번호
x = M[p] XOR C[q]
y = M[q] XOR C[p]

x, y는 사용자가 따로 입력하는 값이 아닙니다. 파일 내용과 정해진 선택 규칙으로 결정됩니다. salt는 이 식에 직접 넣지 않습니다.

앞 네 연산

a = a + b + x
d = ROTR64(d XOR a, 32)
c = c + d
b = ROTR64(b XOR c, 25)

뒤 네 연산

a = a + b + y
d = ROTR64(d XOR a, 16)
c = c + d
b = ROTR64(b XOR c, 11)

연산 흐름은 a → d → c → b입니다. 방금 갱신한 값을 다음 줄에서 사용합니다. 뒤 네 연산도 앞 네 연산의 결과에서 계속 계산합니다.

덧셈 A자리올림으로 비트들이 서로 영향을 줍니다. 넘친 부분은 버리고 하위 64비트만 남깁니다.
회전 R비트를 다른 위치로 옮깁니다. 오른쪽에서 밀려난 비트는 왼쪽으로 돌아옵니다.
XOR X같은 위치의 두 비트가 다르면 1, 같으면 0을 만듭니다.

이 세 연산을 합쳐 ARX라고 합니다. 각 결과가 다음 연산으로 이어지면서 입력의 영향이 퍼집니다.

코드에서 a를 바꾸면 V도 바로 바뀌는 이유

호출할 때 &state.V[0]처럼 V의 주소를 넘깁니다. G 안의 *a는 그 위치의 값을 가리킵니다. 따라서 *a = ...가 곧 해당 V를 갱신하는 연산입니다.

6열 4번 + 대각선 4번 = 한 라운드

G의 계산식은 같습니다. 어느 V 네 개를 함께 계산하느냐가 달라집니다. 버튼을 누르면 선택한 네 위치가 표시됩니다.

이 그림은 숫자를 계산하는 시뮬레이터가 아니라 G가 선택하는 위치를 보여줍니다. 실제로 숫자를 대각선으로 이동시키지는 않습니다.

열 단계에서 각 열의 숫자를 섞은 뒤, 갱신된 값들로 대각선 단계를 실행합니다. 대각선은 서로 다른 열에서 하나씩 골라 열 사이로 정보를 전달합니다.

716라운드 동안 반복하기

한 라운드 = 열 G 4번 + 대각선 G 4번
블록 하나 = 16라운드
G 호출 횟수 = 8 × 16 = 128번

라운드가 바뀌어도 V는 초기화하지 않습니다. 앞 라운드에서 바뀐 값을 그대로 이어서 사용합니다.

메시지 선택 순서는 sigma 표로 바꿉니다. 첫 라운드의 첫 G는 M[0], M[1]을 사용하고, 두 번째 라운드의 첫 G는 M[14], M[10]을 사용합니다. M을 바꾸는 것이 아니라 가져오는 번호를 바꿉니다.

라운드 번호: 0  1  2  …  9  10 11 12 13 14 15
사용할 표:  σ0 σ1 σ2 … σ9  σ0 σ1 σ2 σ3 σ4 σ5

명세에는 순열표가 10개 있습니다. 코드는 반복해서 사용할 행까지 sigma 배열에 미리 기록합니다.

8V의 결과로 H 갱신하기

16라운드가 끝나면 작업 숫자 16개를 기존 H·salt와 결합해 새 H 숫자 8개를 만듭니다.

각 j = 0 … 7에 대해:
새 H[j] = 기존 H[j] XOR s[j mod 4] XOR V[j] XOR V[j+8]

예: 새 H[0] = 기존 H[0] XOR s[0] XOR V[0] XOR V[8]

현재 코드는 salt가 0이므로 H[0] ^= V[0] ^ V[8]로 계산합니다. 나머지 H도 같은 방식입니다.

9다음 블록으로 이어가거나 최종 출력하기

시작 H = IV
    ↓ 블록 0 처리
갱신된 H
    ↓ 블록 1 처리
다시 갱신된 H
    ↓ 마지막 블록 처리
최종 H → 64바이트 해시 출력

새 블록마다 V를 다시 준비하되, 이전 블록에서 만든 H를 사용합니다. 이렇게 앞 블록의 내용도 다음 계산에 영향을 줍니다.

카운터 t는 해당 블록까지 처리한 원래 메시지의 누적 비트 수입니다. 원래 메시지 비트가 전혀 없는 마지막 패딩 블록은 예외적으로 t=0을 사용합니다.

마지막 H는 64비트 숫자 8개입니다. 이를 빅엔디언 바이트로 출력합니다.

64비트 × 8개 = 512비트 = 64바이트
16진수로 표시하면 128자리

M[0], M[1]
